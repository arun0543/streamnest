The terminal prints the addresses, e.g. http://localhost:{{port}} and LAN: http://192.168.x.x:{{port}}. Open the LAN address from any device on your Wi-Fi.


Set the admin password




Until a password is set, only the computer running StreamNest can use it. After you set one, other devices sign in with it. The password is never put in a URL.



2. Add several folders




Windows network folders work as UNC paths when Windows can already open them (try them in Explorer first).






Paths that don't exist or are already added are skipped with a reason; the rest are still added. A running server picks the change up within a couple of seconds. You can also use /admin → Add folders… and tick several folders at once.

4. SMB


Use files that live on a NAS or another PC (client)


Recommended on Windows: add the share as a UNC path. Windows handles passwords, SMB3 and signing for you.




If Windows asks for a login, connect once in Explorer and tick "Remember my credentials", or run (the password stays in Windows' credential store):




Do not type a password on the net use command line itself; it would be visible in process lists and shell history. The * makes Windows prompt for it.


Recommended on Linux: mount the share, then add the mount point as a local folder.




To keep it after reboots, put a credentials file (chmod 600) and a line in /etc/fstab; see docs/SMB.md.


There is also a built-in SMB client (/admin → Add folders → SMB tab). It speaks SMB 2.0.2/2.1 only; it cannot do SMB3 signing or encryption, so use it for NAS boxes that allow SMB2, and prefer the UNC/mount routes otherwise. Passwords you enter are encrypted on disk and never returned by the API.



Share your libraries over SMB (server)


Node can't be a good SMB server, so StreamNest asks your OS to share the folders read-only:




That prints one New-SmbShare … -ReadAccess command per library. To run them, open an Administrator PowerShell and use npm run smb:share -- --apply. On another Windows PC: Explorer → Map network drive → \\this-pc\Share.


That prints a read-only Samba block for each library. Apply it for you with npm run smb:share -- --user {{user}} --apply (uses sudo), then set the SMB password: sudo smbpasswd -a {{user}}.


On Android use VLC → Local network → add SMB, or CX File Explorer → Network → SMB.



5. FTP


Use files on an FTP server (client)


/admin → Add folders → FTP tab: host, port, user, password, security (FTP, explicit FTPS, implicit FTPS) and base path. Press Test connection first. Seeking works (FTP REST), with a small connection pool per library.


Share your libraries over FTP (built-in server, off by default)


In /admin → FTP server: set a username and password, choose a port, and enable. It is always read-only. Then connect from any FTP app to ftp://<this-pc-ip>:{{ftpport}}.


Open the firewall for the control port and the passive port range (default 40000–40100):


Run in an Administrator PowerShell. -Profile Private keeps it off public networks.




Plain FTP sends passwords unencrypted. Use it on your home network only; never forward these ports to the internet.



6. Online mode (share outside your home)


Needs cloudflared installed and an admin password (StreamNest refuses to go online without one).






The terminal prints a https://….trycloudflare.com address. Share links then include an online version (Copy online link).
